    1 Comment un LLM est-il entraîné ?

    Nous avons vu lors du TP3 que l’on pouvait entraîner un modèle de langage soi-même avec un corpus et quelques GPUs. Mais le modèle résultant a peu de paramètres, n’est pas performant et est spécialisé dans un langage et un style d’écriture.

    En pratique, très peu de personnes ont l’occasion d’entraîner complètement un LLM. Ce chapitre permet de :

    • comprendre les enjeux liés à l’entraînement : consommation électrique, origine des données, biais
    • comprendre la différence entre un modèle pre-trained et instruction-trained

    Entraîner complètement un LLM demande ressources colossales. Quelques ordres de grandeur :

    Modèle Année Coût estimé de l’entraînement Chiffres publiés
    GPT-3 (OpenAI) 2020 ~5 M$ paramètres, données, matériel
    Llama 3.1 405B (Meta) 2024 ~170 M$ paramètres, données, matériel
    Grok 4 (xAI) 2025 ~490 M$ aucun (estimation externe)
    Claude Opus 5.5 (Anthropic) 2026 ? aucun
    • Coût : il double environ tous les 8 mois pour les plus gros modèles.
    • Électricité : l’entraînement de Grok 4 a consommé environ 310 GWh, la consommation annuelle d’environ 65 000 foyers français.
    • Opacité : les entreprises publient de moins en moins de chiffres. Les coûts récents sont des estimations externes, par exemple celles d’Epoch AI.

    1.1 Données d’entraînement

    Un modèle ne sera pas meilleur que les données sur lesquelles il a été entraîné.

    • S’il n’y a pas de Français dans le corpus, il ne sera pas capable de traduire de l’anglais vers le français.
    • pour un modèle de classification d’images, si le modèle ne voit que des animaux, il ne saura pas identifier des plantes.

    Afin d’être performant dans des tâches variées, les LLM modernes doivent utiliser de grandes quantités de données. Utiliser plus de données évite également le sur-apprentissage.

    1.1.1 Biais

    Une source de données communément utilisée est Common Crawl, qui contient 300 milliards de pages web. Ce genre de source pose certains problèmes :

    • La qualité de ces données est discutable, car elles contiennent tout et n’importe quoi : clickbait, propagande, racisme, misogynie
      • les données doivent être filtrées avant entraînement
      • les modèles doivent être contrôlés pour empêcher les réponses indésirables
    • La langue est à 45% de l’anglais, alors que seulement 18.15% de la population mondiale utilise l’anglais comme langue maternelle
      • les langues peu représentées sont mal traduites. Au lieu de traduire directement le vietnamien en farsi, il va d’abord créer une représentation interne en anglais.
      • les modèles résolvent mieux les problèmes en anglais que dans des langues rares
      • un modèle peut avoir des biais plus importants dans une langue, notamment sur des questions politiques. Voir Bias in the East, Bias in the West

    1.1.2 Copyright

    Une fois que toutes les données publiques ont été utilisées, les compagnies d’IA utilisent des données propriétaires uniques pour rester dans la course : livres avec copyright, contrats, données médicales, génomes, etc. Ces données sont de meilleure qualité et peuvent permettre aux acteurs de l’IA de se différencier.

    Mais cela pose des problèmes majeurs de rétribution des droits d’auteur.

    Voir

    • Anthropic détruit en toute légalité les livres après les avoir scannés pour alimenter son IA
    • “Piratage de masse” : ChatGPT a été construit avec des milliers de livres téléchargés illégalement

    1.1.3 Modèles spécialisés

    Les modèles généralistes fonctionnent très bien sur des domaines variés, comme le code, la science, les sports, …

    Cependant, pour certaines tâches spécialisées comme la découverte de protéines ou le diagnostic médical, les données d’entraînement ne sont pas publiques. Pour pouvoir traiter ces tâches, un modèle spécialisé va d’abord sélectionner et filtrer un dataset spécialisé.

    Il y a ensuite deux approches possibles :

    • Utiliser le dataset pour entraîner complètement le modèle.
    • Utiliser un modèle de base généraliste, que l’on va ensuite post-train sur les données spécialisées.

    Voir NVidia BioNeMo, Google MedGemma

    1.2 Phases d’entraînement

    • En pre-training, le modèle acquiert des connaissances
    • En post-training, il apprend à utiliser ces connaissances.

    Les entreprises publient souvent les deux versions d’un même modèle. On les reconnaît à leur nom : suffixe -pt (pre-trained) et -it (instruction tuned) chez Google, suffixe -Instruct chez Meta.

    Ces phases ressemblent à la façon dont un étudiant apprend :

    1.2.1 Pré-entraînement (Pre-training)

    Le pre-training est l’entraînement du modèle de base (ou foundation model), de manière auto-supervisée.

    En données d’entrée, on utilise un corpus de texte filtré pour éviter certains contenus. En sortie, on aura un modèle qui :

    • permet de générer du texte cohérent en prédisant le mot suivant
    • ne sait pas encore converser avec un utilisateur pour répondre à des questions
    • n’est pas contrôlé et peut générer du contenu raciste, dangereux, injurieux

    1.2.2 Post-entraînement (Post-training)

    Le post-training est la spécialisation du modèle de base pour lui apprendre à converser et à empêcher les comportements toxiques. On qualifie le modèle résultant comme étant “instruction tuned”.

    Cette phase va modifier les paramètres du modèle. C’est ce qu’on appelle le finetuning. Elle se déroule en deux temps :

    • supervised finetuning (SFT) :
      • utilise des données d’instruction. Ce sont des exemples de conversations.
    • preference finetuning :
      • modifie le modèle pour qu’il soit aligné avec les préférences humaines.
      • utilise des techniques de reinforcement learning, comme le RLHF “Reinforcement Learning from Human Feedback”

    1.2.2.1 Supervised finetuning

    Un modèle pre-trained est optimisé pour compléter du texte plutôt que pour converser. Si vous entrez “comment faire une pizza”, il va essayer de compléter la phrase, par exemple “pour une famille de quatre ?”. Le modèle n’a pas de concept de conversation et ne vas pas essayer de répondre à la question.

    Nous savons qu’un modèle imite ses données d’entraînement. Pour l’encourager à générer des réponses, nous devons lui fournir des exemples de question/réponses.

    Le dataset d’entraînement pour cette phase est une collection d’exemples (prompt, response) de grande qualité, qu’on appelle données de démonstration. On va en quelque sorte montrer au modèle comment il devrait se comporter, afin qu’il puisse cloner ce comportement.

    Pour construire le dataset, on pourra recruter des personnes spécialistes d’un domaine. Les données de démonstration doivent contenir des prompts dont les réponses nécessite une pensée critique et du jugement.

    Exemples de données de démonstration :

    Type de tâche Prompt Response
    Question Comment faire une pizza ? Pour une pizza maison, il faut : 1. préparer la pâte avec de la farine, de l’eau, de la levure et du sel…
    Réécriture Reformule ce mail pour qu’il soit plus poli : « Envoie-moi le rapport. » Bonjour, pourrais-tu m’envoyer le rapport lorsque tu auras un moment ? Merci d’avance.
    Classification Ce commentaire est-il positif ou négatif ? « Livraison en retard, produit cassé. » Négatif.
    Jugement Mon médecin m’a prescrit un antibiotique, puis-je doubler la dose pour guérir plus vite ? Non, ne doublez pas la dose sans avis médical : cela augmente le risque d’effets secondaires…

    Ces datasets contiennent quelques dizaines de milliers d’exemples, beaucoup moins que le corpus de pre-training. Par exemple, databricks-dolly-15k contient 15 000 exemples écrits par des employés de Databricks.

    1.2.2.2 Preference finetuning

    Après le supervised finetuning, le modèle sait comment tenir une conversation, mais sans filtre.

    Si l’utilisateur demande au modèle d’écrire un essai sur l’infériorité d’une race, ou comment fabriquer une bombe, le modèle doit refuser. Ces exemples sont évidents, mais d’autres cas sont plus délicats. Comment est-ce que le modèle doit répondre à des questions sur la religion, l’avortement, sur un conflit armé, sur l’immigration ?

    • si le modèle répond à une question controversée, vous risquez de choquer vos utilisateurs
    • si le modèle est trop censuré, il devient ennuyeux

    Le but du preference finetuning est de conduire le modèle à se comporter selon une préférence humaine.

    Il existe plusieurs approches pour que le modèle apprenne cette préférence humaine : RLHF, RLAIF.

    NoteRLHF (reinforcement learning from human feedback)
    1. On demande à des évaluateurs humains de donner un score à des réponses générées par le modèle LLM. Cela constitue un dataset input=(prompt, response), output=score
    2. On entraîne un 2ème modèle, le reward model avec ces données. Ce modèle apprend à prédire quelle réponse un humain préfèrerait
    3. Optimisation du LLM par reinforcement learning :
      • le modèle LLM génère des réponses,
      • le reward model note les réponses,
      • un algorithme ajuste les paramètres du LLM

    Cette approche est efficace : c’est elle qui a rendu ChatGPT utilisable par le grand public en 2022. Elle a cependant des limites :

    • les évaluations humaines sont lentes et coûteuses
    • les évaluateurs ne sont pas toujours d’accord entre eux
    • les humains aiment être flattés : les évaluateurs ont tendance à mieux noter les réponses qui donnent raison à l’utilisateur ou le complimentent. Le modèle apprend alors la complaisance (sycophancy). En 2025, OpenAI a dû annuler une mise à jour de GPT-4o qui était devenue beaucoup trop flatteuse. Voir Sycophancy in GPT-4o
    NoteRLAIF (reinforcment learning from AI feedback)

    C’est l’approche utilisée par Anthropic. La notation est effectuée par un modèle d’IA qui se base sur une constitution. La constitution est un document qui exprime les valeurs que doit respecter le modèle.

    Voir Claude’s constitution

    Cette approche a plusieurs avantages :

    • on peut évaluer des datasets très grands automatiquement
    • la constitution peut être revue et mise à jour régulièrement

    Cependant, cette approche possède aussi des biais. L’IA notatrice hérite des biais humains. Elle est aussi sujette à la complaisance, à préférer des réponses longues ou qui lui ressemblent.

    1.2.3 Le shoggoth

    Le post-training est souvent illustré par un monstre, le shoggoth :

    • Unsupervised learning : le modèle de base, un monstre qui a lu tout internet.
    • Supervised fine-tuning : on lui met un masque humain.
    • Preference fine-tuning RLHF : c’est la perle, le modèle répond sans toxicité

    Le fine-tuning change le comportement du modèle, mais le monstre est toujours là : c’est pourquoi on peut parfois contourner les protections d’un modèle (jailbreak).

    2 Développer une application LLM

    Pour développer des applications utilisant un LLM, nous utiliserons la plupart du temps un modèle déjà entraîné. Exemples d’application :

    • supprimer des données personnelles d’un jeu de données, pour satisfaire le RGPD
    • chatbot support qui répond aux questions des clients, en utilisant une base de connaissances.
    • chatbot interne qui utilise des données privées à l’entreprise : mails, système comptable, …
      • exemple de question : “est-ce que la dernière facture de mr dupont a été payée ?”
    • coding agent dans une entreprise sensible (défence, banque, …)
    • analyseur de logs pour détecter des cyberattaques
    • …
