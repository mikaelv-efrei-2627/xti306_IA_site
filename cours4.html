    1 Comment un LLM est-il entraîné ?

    On peut entraîner un petit modèle de langage soi-même, avec un corpus de textes et quelques GPUs (voir le TP3b, facultatif, dans l’annexe du CM3). Mais le modèle résultant a peu de paramètres, n’est pas performant et est spécialisé dans un langage et un style d’écriture.

    En pratique, très peu de personnes ont l’occasion d’entraîner complètement un LLM. Ce chapitre permet de :

    • comprendre les enjeux liés à l’entraînement : consommation électrique, origine des données, biais

    Les phases d’entraînement (pre-training, post-training) sont présentées dans le CM3.

    Entraîner complètement un LLM demande des ressources colossales. Quelques ordres de grandeur :

    Modèle Année Coût estimé de l’entraînement Chiffres publiés
    GPT-3 (OpenAI) 2020 ~5 M$ paramètres, données, matériel
    Llama 3.1 405B (Meta) 2024 ~170 M$ paramètres, données, matériel
    Grok 4 (xAI) 2025 ~490 M$ aucun (estimation externe)
    Claude Opus 5.5 (Anthropic) 2026 ? aucun
    • Coût : il double environ tous les 8 mois pour les plus gros modèles.
    • Électricité : l’entraînement de Grok 4 a consommé environ 310 GWh, la consommation annuelle d’environ 65 000 foyers français.
    • Opacité : les entreprises publient de moins en moins de chiffres. Les coûts récents sont des estimations externes, par exemple celles d’Epoch AI.

    1.1 Données d’entraînement

    Un modèle ne sera pas meilleur que les données sur lesquelles il a été entraîné.

    • S’il n’y a pas de Français dans le corpus, il ne sera pas capable de traduire de l’anglais vers le français.
    • pour un modèle de classification d’images, si le modèle ne voit que des animaux, il ne saura pas identifier des plantes.

    Afin d’être performant dans des tâches variées, les LLM modernes doivent utiliser de grandes quantités de données. Utiliser plus de données évite également le sur-apprentissage.

    1.1.1 Biais

    Une source de données communément utilisée est Common Crawl, qui contient 300 milliards de pages web. Ce genre de source pose certains problèmes :

    • La qualité de ces données est discutable, car elles contiennent tout et n’importe quoi : clickbait, propagande, racisme, misogynie
      • les données doivent être filtrées avant entraînement
      • les modèles doivent être contrôlés pour empêcher les réponses indésirables
    • La langue est à 45% de l’anglais, alors que seulement 18.15% de la population mondiale utilise l’anglais comme langue maternelle
      • les langues peu représentées sont mal traduites. Au lieu de traduire directement le vietnamien en farsi, il va d’abord créer une représentation interne en anglais.
      • les modèles résolvent mieux les problèmes en anglais que dans des langues rares
      • un modèle peut avoir des biais plus importants dans une langue, notamment sur des questions politiques. Voir Bias in the East, Bias in the West

    1.1.2 Copyright

    Une fois que toutes les données publiques ont été utilisées, les compagnies d’IA utilisent des données propriétaires uniques pour rester dans la course : livres avec copyright, contrats, données médicales, génomes, etc. Ces données sont de meilleure qualité et peuvent permettre aux acteurs de l’IA de se différencier.

    Mais cela pose des problèmes majeurs de rétribution des droits d’auteur.

    Voir

    • Anthropic détruit en toute légalité les livres après les avoir scannés pour alimenter son IA
    • “Piratage de masse” : ChatGPT a été construit avec des milliers de livres téléchargés illégalement

    1.1.3 Modèles spécialisés

    Les modèles généralistes fonctionnent très bien sur des domaines variés, comme le code, la science, les sports, …

    Cependant, pour certaines tâches spécialisées comme la découverte de protéines ou le diagnostic médical, les données d’entraînement ne sont pas publiques. Pour pouvoir traiter ces tâches, un modèle spécialisé va d’abord sélectionner et filtrer un dataset spécialisé.

    Il y a ensuite deux approches possibles :

    • Utiliser le dataset pour entraîner complètement le modèle.
    • Utiliser un modèle de base généraliste, que l’on va ensuite post-train sur les données spécialisées.

    Voir NVidia BioNeMo, Google MedGemma

    2 Développer une application LLM

    Pour développer des applications utilisant un LLM, nous utiliserons la plupart du temps un modèle déjà entraîné. Exemples d’application :

    • supprimer des données personnelles d’un jeu de données, pour satisfaire le RGPD
    • chatbot support qui répond aux questions des clients, en utilisant une base de connaissances.
    • chatbot interne qui utilise des données privées à l’entreprise : mails, système comptable, …
      • exemple de question : “est-ce que la dernière facture de mr dupont a été payée ?”
    • coding agent dans une entreprise sensible (défence, banque, …)
    • analyseur de logs pour détecter des cyberattaques
    • …

    Pour chaque solution, vous devrez définir des critères de succès :

    • est-ce qu’elle répond au besoin ?
    • est-ce qu’elle est fiable : faux positifs, faux négatifs, hallucinations ?
    • est-ce qu’elle permet d’éviter les propos toxiques ?

    • quel est son coût de développement ? : développement de la solution, entraînement, tests ?
    • quel est son coût d’inférence par requête ? : coût API / coûts serveurs ?
